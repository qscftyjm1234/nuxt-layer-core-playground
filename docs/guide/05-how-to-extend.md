# 如何安全地擴充核心架構

了解了設計哲學後，實戰中難免會遇到「核心層提供的東西不夠用」或是「這個專案有特殊需求」的狀況。本課將教您如何在這個強依賴架構下，正確地進行「擴充」與「覆蓋」，而不破壞核心結構。

---

## 1. 擴充與覆蓋 UI 組件

如果您發現在目前的業務專案中，核心包提供的 `<ICard>` 樣式不符合客戶需求，您可以利用 Nuxt Layer 強大的「同名覆蓋」機制。

**做法：**
在您專案的 `components/uiInterface/` 之下，建立一個與核心包「名稱完全一樣」的 `ICard.vue`。

**效果：**
Nuxt 會優先使用您業務專案下的這個檔案。這代表您成功在「只有這個專案」的範圍內覆蓋了核心樣式，而沒有影響到提供給其他專案的公共核心庫！

## 2. 累加設定：擴展設定檔

在業務專案中，您可以在您的 `nuxt.config.ts` 內安心撰寫設定。Nuxt Layer 的機制會聰明地將業務端的設定與核心端的設定「合併」。

例如：

```typescript
// 業務端的 nuxt.config.ts
export default defineNuxtConfig({
  extends: ['softleader-nuxt-core'],

  // 這個專案自己需要的模組，會與核心層內建的模組累加，不會覆蓋掉原始的設定
  modules: ['@nuxt/image']
})
```

## 3. 擴展 API 與倉庫

如果核心層提供了一個共用的 `modules/user.ts`，但這個業務專案有一個特別的客製化會員 API。您不應去更改核心包，而是：

1. 在業務專案下建立 `repositories/modules/customUser.ts`。
2. 在該檔案中，您可以建立該專案專屬的 endpoint，並同樣透過核心提供的 `useApi()` 發送請求，達成完全與核心層隔離的擴充。

## 4. 判斷依賴安裝的邊界

在 Monorepo 開發時，請遵守以下安裝依賴的判斷準則：

- **共用依賴**：如果這個套件 (如 `dayjs`, `pinia`, Ui 框架) 是每個後續專案**絕對**會用到的，請安裝在 `packages/nuxt-core/package.json` 的 `dependencies`。
- **專案特有依賴**：如果這個套件 (如某個特定的 3D 繪圖庫、特定的圖表庫) 只是「當下這個專案」的客戶需要，請直接安裝在該業務專案的 `package.json`，千萬不要丟進核心包去加重其他不相干專案的負擔。
