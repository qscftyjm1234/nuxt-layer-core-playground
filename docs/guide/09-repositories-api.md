# API 請求與倉庫模式 (Repositories)

本專案規定所有的 API 請求必須統一透過架構層管理，嚴禁在元件內任意發送零散的請求。

## 1. 核心規範：使用 `useApi`

所有的 API 呼叫必須透過核心包封裝好的 `useApi` 機制，或是已建立好的 Repositories。

- **禁止**：直接使用原生 `fetch` 或自建 `axios` 實例。
- **原因**：核心層的 API 模組內建了統一的攔截器、錯誤處理 與授權機制。繞線呼叫會造成安全性漏洞與重複造輪子。

## 2. 倉庫模式

為了讓 API 呼叫更具語意化並方便跨元件共用，我們採用了 Repository 模式。將 API 行為依據業務模組收攏在 `repositories/` 下。

### 觀念說明

1. 將同一個業務領域的 API 請求（如用戶相關、訂單相關）集中在一個 Repository 檔案中。
2. 開發者透過宣告 Repository 來使用，不需硬記實體網址路由。這讓改版或重構時能統一處理參數變更。

### 開發步驟

1. **定義 Repository**：在 `repositories/` 下建立模組類別或方法集合。
2. **組織請求**：內部整合 `useApi` 以統一處理遠端呼叫。
3. **元件套用**：介面開發者只需引入該 Repository 並呼叫對應方法，無須處理繁瑣的網路連線設定。
